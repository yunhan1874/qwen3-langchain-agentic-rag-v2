# 真实模型延迟优化验收

测试日期：2026-10-26。模型为用户的 Qwen3-1.7B `checkpoint-1082`，GPU 为 RTX 4090，BF16；使用相同的 BGE Embedding、CrossEncoder 和 2,502 个 chunk 的 Chroma 索引。

## 变更

- 首轮使用原始问题和显式过滤条件直接检索，证据分数不足才调用 Qwen 改写。
- 改写和重试共享最多新增 96 token 的预算，回答最多新增 256 token；两者复用同一模型。
- 改写 JSON 截断或字段无效时规则降级。
- 最多检索 3 轮；最后一轮失败直接拒答，不生成下一条无法执行的查询。
- 初始低分重写后使用对应查询压缩证据；显式过滤条件优先于模型推断。

## 页面端到端计时

通过本机 SSH 隧道调用 Gradio `/handle_request`，计时包含排队和网络开销。旧服务已加载模型；新服务排除一个冷启动预热请求。生成保留原采样设置，输出长度可变；以下为小样本实测，并非固定延迟或医学质量指标。

| 请求 | 改前（秒） | 改后（秒） |
|---|---:|---:|
| 高血压问题，第 1 次记录 | 17.908 | 6.088 |
| 高血压问题，第 2 次记录 | 24.016 | 4.405 |
| 高血压问题，第 3 次记录 | 未测 | 5.522 |
| 糖尿病问题 | 69.823 | 另测引擎耗时 6.815；未测页面计时 |

高血压问题：`高血压患者日常如何管理血压？`。改后页面三次常驻请求中位数 5.522 秒、均值 5.339 秒，每次均为 `answered`、3 条 Citation、最高分 0.9569。改前两次高血压请求的中位数为 20.962 秒；与改后三次中位数相比约减少 73.7%，但样本数与采样输出不同，该比例仅描述本次记录。

新服务首个冷启动预热请求耗时 20.218 秒，不包含在上述改后三次统计中。服务随后保持模型常驻。

## GPU 引擎与预算验证

拦截临时测试进程的实际 `model.generate` 调用，记录生成上限和输出 token；运行中的服务不安装拦截逻辑。

| 问题 | 总耗时（秒） | LLM 调用数 | 回答 token | 上限 |
|---|---:|---:|---:|---:|
| 高血压，第 1 次 | 6.683 | 1 | 135 | 256 |
| 糖尿病 | 6.815 | 1 | 153 | 256 |
| 高血压，第 2 次 | 5.975 | 1 | 134 | 256 |

三次均正常回答、有 3 条引用，回答无 `<think>` 标记，未触及回答 token 上限。

强制首轮空召回的集成测试中，Qwen 改写使用 96 token 上限并触及上限；规则降级后第二轮检索成功，回答生成 166 token（上限 256），状态 `answered`。这验证了截断降级，不代表此次短预算下 Qwen JSON 改写成功。

无匹配来源过滤条件的测试中，仅发生一次 96 token 改写；规则降级产生重复查询后停止，状态 `abstained`，无 Citation、无回答生成调用。有效改写后检索成功、低分非空召回、三轮耗尽和末轮无多余改写另有单元测试覆盖。
