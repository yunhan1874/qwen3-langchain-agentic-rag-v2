# vLLM 优化消融测试

测试日期：2026-10-27。使用用户真实训练的 Qwen3-1.7B `checkpoint-1082`。

此次固定长度测试中，CUDA Graph 对生成耗时的影响最大；编译在关闭图执行时仍有收益。Flash Attention 与 Triton Attention 的耗时差异小于首尾基准波动，不能据此确定更优后端。前缀缓存主要改善重复长输入的首文本延迟，并发主要提高总吞吐量。

正式前端和 vLLM 服务全程保持运行，配置未修改。测试结束后临时服务已停止；正式服务、前端及本地隧道均返回 HTTP 200。

## 测试条件

- RTX 4090 24 GB，驱动 580.178.04；BF16，单 GPU。
- vLLM 0.11.0，PyTorch 2.8.0+cu128，Transformers 4.57.6。同一个环境、检查点和测试客户端。
- 独立测试服务监听 `127.0.0.1:8002`，显存预算 25%。正式服务仍使用 50% 预算；本次绝对耗时不是生产 SLA。
- 最大上下文 4,096，最大序列数 4，批次 token 预算 4,096；CUDA Graph 捕获大小 `[1,2,4]`。
- 短输入为真实 RAG 生成提示词，693 token；长输入为该提示词的重复前缀加原提示词，3,093 token，用于模拟更长上下文。
- 贪心解码，seed=0，`min_tokens=max_tokens=128`，`ignore_eos=true`。每个输入形状先预热 2 次，再测 5 次；交替短、长输入顺序。
- 共 80 次串行测量，另有 24 次请求用于并发探测。预热不纳入结果。
- 总耗时从发出 HTTP 请求到 SSE 完成；TTFT 从请求开始到首个非空文本分片，包含客户端和本机 HTTP 开销，不保证对应恰好一个 tokenizer token。
- 下面均为中位数；所有请求输出长度均经服务端 usage 校验为 128 token。计时不包含检索、精排、Gradio、SSH 隧道和浏览器。

## 图执行、编译和 Attention

除表中特别说明外，使用 Flash Attention，前缀缓存关闭。

| 配置 | 短输入总耗时 / 秒 | 短输入 TTFT / 毫秒 | 长输入总耗时 / 秒 | 长输入 TTFT / 毫秒 |
|---|---:|---:|---:|---:|
| 基准：编译 level=3，FULL_AND_PIECEWISE 图执行 | 0.7650 | 42.9 | 0.8667 | 106.2 |
| 编译 level=3，关闭 CUDA Graph | 2.3307 | 36.5 | 2.3720 | 101.8 |
| 编译 level=0，关闭 CUDA Graph | 2.6081 | 40.3 | 2.6404 | 101.6 |
| 编译 level=0，仅 FULL_DECODE_ONLY 图执行 | 0.7893 | 36.9 | 0.8988 | 105.3 |
| 基准配置，改用 Triton Attention | 0.7513 | 45.5 | 0.8516 | 113.4 |
| 末尾基准复测 | 0.7797 | 33.8 | 0.8866 | 102.2 |

1. **CUDA Graph：**在编译开启时，启用图执行使短、长输入总耗时分别降低约 **67.2% / 63.5%**。短输入的首文本之后耗时由 2.2950 秒降到 0.7222 秒，收益主要体现在后续逐 token 解码，首文本延迟没有改善。
2. **编译：**在图执行关闭时，level=3 相比 level=0 使短、长输入耗时分别降低约 **10.6% / 10.2%**。这是该条件下的贡献，不能外推为生产配置中编译的独立贡献。
3. **解码图交叉验证：**关闭编译、仅启用解码图时，耗时恢复到 0.7893 / 0.8988 秒，也支持本次小模型、单请求、固定输出场景主要受益于图执行。该图模式与基准不同，不能将两者的差直接解释为编译的贡献。
4. **Attention 后端：**Triton 相比首次基准仅快约 1.8% / 1.7%，而首尾基准总耗时变化约 1.9% / 2.3%，且 Triton 的首文本延迟更高。这组数据不足以支持切换后端。

日志核验了实际配置：基准和 Triton 均为 level=3、`cudagraph_mode=[2,1]`；无图组为 mode=0；无编译解码图组为 level=0、mode=`[2,0]`。对应 Attention 后端和成功捕获图日志均已记录，没有以启动命令代替实际生效情况。

首次基准总耗时范围：短输入 0.7622–0.7880 秒，长输入 0.8610–0.8730 秒。末尾基准范围：短输入 0.7585–0.7894 秒，长输入 0.8616–0.8963 秒。没有进行随机化轮换或统计显著性检验，小于该量级的差异不宜过度解读。

## 前缀缓存：冷缓存与命中缓存

同一个启用缓存的测试服务，每轮先清空缓存测冷请求，再发送完全相同的提示词测命中请求。逐次检查服务端 `cached_tokens`；冷请求全部为 0，命中请求分别为 688 和 3,088。

| 输入 | 缓存状态 | 总耗时 / 秒 | TTFT / 毫秒 | 命中 token 数 |
|---|---|---:|---:|---:|
| 短，693 token | 冷 | 0.7693 | 39.6 | 0 |
| 短，693 token | 命中 | 0.7700 | 36.9 | 688 |
| 长，3,093 token | 冷 | 0.8761 | 106.0 | 0 |
| 长，3,093 token | 命中 | 0.8188 | 48.4 | 3,088 |

长输入命中后，TTFT 降低约 **54.4%**，总耗时降低约 **6.5%**；短输入总耗时基本不变。前缀缓存复用已有前缀的 KV，主要节省 prefill，不会省掉这 128 个新 token 的生成。真实查询是否受益取决于公共前缀长度、命中率和缓存保留情况。

第一次缓存组因重置接口返回 404 失败，未计入有效样本。核对 vLLM 0.11 源码后，仅在临时缓存测试进程设置 `VLLM_SERVER_DEV_MODE=1`，开放 `/reset_prefix_cache`，补测成功。正式服务未开启该开发开关，正式服务的前缀缓存仍然关闭。

## 四请求并发探测

使用基准服务和短输入，比较四请求顺序完成与四客户端同时提交。每个请求输出 128 token；每种方式重复 3 批。总吞吐按每批 512 token / 批次墙钟耗时计算。

| 方式 | 四请求完成耗时 / 秒 | 总输出吞吐 / token/s | 单请求耗时中位数 / 秒 | 单请求 TTFT 中位数 / 毫秒 |
|---|---:|---:|---:|---:|
| 串行 | 3.0688 | 166.8 | 0.7630 | 39.8 |
| 并发 4 | 0.9502 | 538.8 | 0.9464 | 94.3 |

并发总吞吐约为串行的 **3.23 倍**，同时单请求耗时和 TTFT 增加。这验证了引擎处理并发请求时的吞吐收益，没有做“关闭连续批处理”的调度器消融，不能据此量化调度算法本身的独立贡献。当前 Gradio 并发限制仍为 1，这个结果不代表页面已支持四路并发。

## 一致性与解释边界

- 每个串行条件内部，五次输出文本哈希均一致；不同条件间并不全部一致。短输入中，无编译组、Triton 组和缓存命中组出现与基准不同的输出哈希；长输入跨组一致。固定长度只控制计算工作量，没有证明医学回答质量或 Faithfulness 等价。
- 所有优化存在交互，上述降低比例使用不同的条件基线，**不能相加**，也不能用于分摊之前 Transformers 与 vLLM 的全部差异。
- 没有独立关闭 PagedAttention/KV 分页分配的等价对照，因此不报告它的独立提速比例。前缀缓存测试也不等价于关闭普通生成 KV cache。
- 正式服务和 BGE 常驻同一张 GPU；未锁定 GPU 时钟。样本较少，长输入为合成重复，结果只支持本次场景的工程判断。
- 本地完整 32 项单元测试通过。服务器原有测试目录仍保留优化前断言，初次运行有两项失败；在独立输出目录上传当前仓库测试快照后，服务器同样 32 项全部通过，无需改动运行中的业务代码。

## 数据与复现

[机器可读记录](benchmarks/vllm_ablation_20261027.json) 包含逐次耗时、输出和提示词 SHA-256、命中 token 数、配置及日志证据；检查点路径已替换为占位符，不含原始医疗段落或模型回答。

复现脚本：[scripts/ablate_vllm.py](../scripts/ablate_vllm.py)。先配置 README 中的真实 RAG 路径，在 Linux 服务器项目根目录执行：

```bash
# 使用已安装项目依赖的环境，仅捕获生成提示词，不额外加载 Qwen 权重。
python scripts/ablate_vllm.py \
  --prepare-fixtures --model /path/to/checkpoint-1082 \
  --output-dir output/vllm_ablation

# 使用独立 vLLM 环境作为测试引擎。
python scripts/ablate_vllm.py \
  --model /path/to/checkpoint-1082 \
  --vllm-python /path/to/vllm-venv/bin/python \
  --output-dir output/vllm_ablation \
  --repeats 5 --memory-fraction 0.25
```

`private_prompts.json` 只保存在已忽略的 `output/`，不应提交公开仓库。测试端口被占用时脚本拒绝启动；仅终止自己创建的进程组。可用 `--variants no_graph` 等参数只测指定组。
