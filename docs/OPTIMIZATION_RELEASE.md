# 优化落地与真实模型复测

日期：2026-10-27。此次将审计中确认的检索优化和可靠性修复落地，并更新服务器展示前端。继续使用用户真实训练的 Qwen3-1.7B `checkpoint-1082` 和 vLLM；候选数、精排 FP32、0.28 阈值、回答 256 / 改写 96 token 预算及提示词格式保持原配置。

## 已实现

1. **BM25 倒排。**构建索引时预计算词项得分，查询时访问倒排列表；保留重复查询词及原浮点累加顺序。过滤无匹配时立即返回。
2. **显式过滤空匹配预检查。**本地元信息已证明没有任何满足硬过滤条件的文档时，直接拒答，不再调用 Dense、精排或 Qwen 改写。一般低分查询仍按原流程改写。
3. **引用状态。**不再在模型缺少引用时自动补 `[1]`。页面显示“模型未生成引用”或“模型已引用，事实支持待核验”，将相关度明确标为“检索相关度”。检索证据清单仍可查看；结构化 Citation 新增完整压缩 `evidence`，保留原 180 字 `excerpt`。
4. **思考块清理。**完整块、未闭合块及预填充思考块的剩余内容会被清理。清理后没有可见回答时返回 `generation_failed`，不再作为成功回答展示。
5. **版本索引。**基于原语料内容、来源路径、Embedding 配置/权重文件及分块参数计算指纹，将缓存写入 `RAG_INDEX_DIR/versions/<指纹>/`。旧索引保留；新版本独立生成。缓存文件通过临时文件和原子替换写入。
6. **向量内容核验。**复用 Chroma 时逐批检查 ID、文本及元信息；数量相同也不能跳过核验。遇到内容不一致时明确报错，不再自动删除旧集合。显式 `--rebuild-index` 仍可重建目标版本。
7. **评估口径。**评估器调用与页面相同的 LCEL。输出词汇支持代理、句子精确匹配、拒答率和合法引用率；语义 `faithfulness` 明确为 `null / not_evaluated`。代理只评估成功回答，读取完整压缩证据。

句子精确匹配是保守的文本指标，不是语义评估。否定、剂量反例的精确匹配为 0；原词汇代理仍可能为 1，现已如实标注，不再称其为已测得的事实忠实度。原函数 `faithfulness_score` 仅保留为词汇代理的兼容别名。

## 前后对比

保存修改前的源代码快照，与新代码在同一服务器、同一模型服务上交替执行。每题每个版本 3 次，使用生产采样参数并固定 seed=0；先预热。耗时包含 LCEL、检索、精排、压缩、生成及本机模型 HTTP 开销，不包含 Gradio 和 SSH。

| 问题 | 修改前中位耗时 / 秒 | 修改后中位耗时 / 秒 |
|---|---:|---:|
| 血压日常管理 | 0.9060 | 0.8809 |
| 血糖监测 | 0.9085 | 0.8850 |
| 用药注意事项 | 1.5901 | 1.5687 |
| 领域外：火箭推力 | 0.6732 | 0.6563 |
| 无匹配的显式 source | 0.6043 | 0.0088 |

无匹配过滤条件的拒答耗时降低约 **98.6%**，没有调用 Qwen。普通问题省约 21–25ms，整体约改善 1.3–2.8%；Qwen 生成仍占主要耗时。样本较少、未锁定 GPU 时钟，不应将这些数值视为任意问题的延迟承诺。

另对相同短查询各做 10 次 BM25 单阶段计时：

| 问题 | 修改前 / 毫秒 | 修改后 / 毫秒 |
|---|---:|---:|
| 血压管理 | 18.205 | 4.693 |
| 血糖监测 | 17.404 | 4.427 |
| 用药注意事项 | 18.082 | 5.302 |
| 火箭推力 | 14.432 | 4.430 |
| 空 source 过滤 | 1.353 | 1.379 |

最后一行单测只调用 BM25，自身仍需检查过滤条件。完整 Agent 的空过滤预检查会更早结束，这两项计时不可混淆。

## 一致性及可靠性验证

- 全部 **2,502 个 chunk ID** 与旧版一致；新版本 manifest 匹配，旧索引仍存在。
- 全部 15 对端到端请求的最终证据 ID、顺序和状态一致；可回答请求的原始模型输出 SHA-256 一致。缺少原生引用时，最终展示文本按设计不再补编号。
- 实际 Chroma 临时库验证：写入 `old` 后传入相同数量的不同 `new`，新代码拒绝复用，且原 `old` 数据完整保留；未触碰真实医疗索引。
- 本地和服务器 **43 项单元测试通过**，新增对倒排精确分数、空过滤、引用状态、生成失败、思考块、完整证据评估及版本指纹的回归覆盖。
- 原始医疗问题、段落和模型回答没有写入公开报告或结果数据。

这次没有做医学答案人工评分或语义蕴含评估，也没有启用 FP16、减少候选数、强制 JSON 解码或修改模型权重。原生引用能力仍需通过模型/提示词和独立质量集进一步验证。

## 缓存及评估兼容说明

首次运行新版会生成一个独立版本索引，之后同一指纹复用。模型为本地目录时校验配置和权重内容；远程模型 ID 请用 `RAG_EMBEDDING_REVISION` 固定不可变的 commit。旧的根目录 `chunks.jsonl` 与 `chroma/` 不会被自动删除，也不会作为新版缓存直接信任。旧版本索引清理由维护者按实际需要执行。

评估 JSON 中的 `faithfulness` 从旧代理分数变为 `null`，原分数迁到 `lexical_support_proxy`。新增的 `exact_sentence_support` 不支持把同义改写自动视为一致；`citation_rate` 也只表示合法编号存在，不证明语义支持。

[逐次复测数据](benchmarks/optimization_release_20261027.json)；复现入口为 [verify_optimizations.py](../scripts/verify_optimizations.py)，需要一个未修改源码包路径作为基准：

```bash
python scripts/verify_optimizations.py \
  --baseline-package /path/to/old/rag_v2 \
  --output output/optimization_release/verification.json
```

基准和新版本需分别能读到旧索引与新版缓存；配置真实路径和 vLLM 后端后运行。脚本只输出耗时、哈希和检查结果。
